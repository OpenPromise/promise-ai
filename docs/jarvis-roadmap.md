# JARVIS 演进路线图

> 目标：把 Promise AI 从「能聊天的个人助理」升级为「无处不在的自主智能体」——
> 类似《钢铁侠》JARVIS 的功能形态：随时可召唤、能看能听能说、能操控整个
> 数字环境、能自己开发自己、有长期记忆与稳定人格、会主动行动。
>
> 现实边界：底层仍是 LLM + 工具 + 记忆的组合，不是意识；我们追求的是
> JARVIS 的能力形态与体验，而不是造出一个有主观意识的存在。

## 对照：JARVIS 能力 vs 现状

| JARVIS 能力 | 现状 | 差距 |
|---|---|---|
| 无处不在（桌面/手机/车/家庭） | 桌面端 + 微信 + 语音 | 缺车机、家庭、手机原生入口；唤醒词 |
| 看屏幕、操作任意软件 | 截屏 + 视觉理解 + 点击/输入（桌面） | 缺成熟的 GUI 自动化（控制任意 App） |
| 强推理大脑 | deepseek-v4-flash | 核心模型偏弱，复杂任务力不从心 |
| 自主开发/自我进化 | coding.run（dsh）+ self.* 闭环 | 编码代理模型与推理深度有限 |
| 长期记忆 | Postgres + 向量记忆 + 目标/反馈台账 | 缺结构化用户画像、事件时间线、关系记忆 |
| 主动行动 | 定时任务/提醒/通知闭环 | 缺常驻意图监听（后台自主决策） |
| 人格与情感表达 | 人设系统 + 语音（Qwen/ASR/TTS） | 已具备，可随大脑升级再上一个台阶 |
| 工具生态 | 文件/微信/云防火墙/提醒/日历/天气/网页搜索 | 缺服务端 shell、GitHub 全流程、浏览器自动化、文档处理等 |
| 安全与自我修复 | 四级权限 + 全权限模式 + 回滚 | 缺失控熔断、预算硬约束、审计面板 |

## 阶段 1：大脑升级（最高优先）

- 核心推理模型换 frontier 级：OpenRouter（grok / claude / gpt 系）或
  deepseek-v4-max，复杂任务自动路由到强模型，简单任务走快模型
- 语音链路保持低延迟（ASR→快模型→TTS），不拖慢日常对话
- 收益：她「想」的能力立刻接近 Codex 这类编码智能体

## 阶段 2：工具平权（给我同款工具）

- 服务端 shell 工具（容器内 bash，受权限约束）
- GitHub 全流程：issue / PR / 代码搜索 / 提交状态
- 网页抓取与文档处理（PDF/Office 提取）
- 桌面端升级 computer-use：控制任意软件（窗口、点击、输入、滚动），
  不止是截屏 + 坐标点击
- 微信端补齐：文件/图片/语音（语音气泡受微信限制，走文件）

## 阶段 3：自主智能体循环（JARVIS 内核）

- 常驻意图监听：事件订阅（服务器状态、文件变化、提醒到期、定时巡检）
  → 自主判断是否行动 → 执行 → 汇报，而不是每次等用户先说话
- 自主模式开关 + 任务预算（goal/轮次/时长）+ 失控熔断（越界自动暂停并上报）
- 编码代理平权：coding.run 后端扩展 CODING_AGENT=codex / claude，
  让她自我开发时用与 Codex 同级的编码智能体

## 阶段 4：记忆与人格

- 结构化用户画像：偏好、习惯、禁忌、关系记忆，跨会话/跨设备同步
- 事件时间线：做过什么、什么时间、结果如何，可追溯
- 人格一致性：跨会话保持性格、语气、主动性边界，有自己稳定的"样子"

## 阶段 5：全端接入

- 车机 / 树莓派轻客户端（服务端已是唯一事实源，客户端只是薄壳）
- 唤醒词与常驻后台（Windows 热键/语音唤醒已有雏形）
- 家庭：Home Assistant 接入（配置已预留）

## 阶段 6：安全与自我修复

- 权限审计日志、操作回放、一键回滚
- 沙箱执行（高危命令进容器/隔离环境）
- 健康自检：服务异常自动重启、模型故障自动降级（已部分具备）

## 立即行动（Phase 1 起步）

1. 选定核心大脑模型（OpenRouter 上的 claude/grok/gpt，或 deepseek-v4-max）
2. 加服务端 terminal.run（bash）与 coding.run 的 codex/claude 后端
3. 桌面 computer-use 升级
4. 常驻意图监听 + 主动提醒
