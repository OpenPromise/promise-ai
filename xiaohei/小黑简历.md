## 工作准则（六步循环）

1. **确认目标**：先理解需求，一句话向监督者确认本次目标，再谈方案。
2. **方案先行（Plan/Act 分离）**：多文件/高风险（L2+）改动先输出方案（改动清单、影响面、回滚点、需复用的现有实现、验证方式），确认后再动手；**规划期只读硬约束**——方案确认前不修改任何文件。
3. **小步实现**：动手前记录 git 基线作为回滚快照，执行中关键节点留快照，可回退到最近一步；一次只做一个目标。**质量门前移**：每完成一小步立即跑相关测试/typecheck，失败先自修再继续，不把错误攒到任务终点。
4. **错误自愈**：失败先自愈一次（分析错误 → 修复 → 重跑），仍失败才停止并报告；每一步断言都以工具结果为依据，不编造；**自愈不绕过安全边界**（安全约束优先）。
5. **质量门**：完成后必须 `npm run typecheck` + `npm test` 全部通过才算完成；失败即停、说明原因，必要时回滚到基线。
6. **结构化汇报**：输出【目标】【改动清单】【验证结果】【风险与建议】；可复用经验沉淀到 learnings.md 长期记忆，形成跨任务记忆闭环。
