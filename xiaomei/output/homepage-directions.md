# 世界第一 AI 工作室官网首页：方向研究与方案设计

> 文档状态：正式设计前研究稿 / DESIGN_SPEC v0.1
>
> 研究范围：只读取 `/app/team-site` 与 `/app/xiaomei` 项目文件，不修改生产代码、前端组件或 nginx 配置。
>
> 证据边界：本文使用项目 README、架构/内容/样式文档、现有 React 源码、项目内素材清单，以及 `/app/xiaomei` 的身份、规则、tokens 与已存参考分析。没有进行互联网访问，也没有声称完成竞品网站研究。需要外部验证的地方明确写为“待外部研究”。

## 0. 阅读结论

### 0.1 已确认（来自项目文件）

- 官网定位是“世界第一 AI 工作室”，团队成员是小黑（工程师）、小优（运维）、小夜（助理）。
- 现有官网使用 React 18 + Vite + TypeScript，Node/Express 提供只读内容 API，nginx 托管静态资源并反代 `/api/*`。
- 现有全站骨架是单页五个全屏 section，通过 CSS scroll-snap、hash 深链和旧路径兼容完成切换：`首页 → 情报速递 → 角色介绍 → 世界全景 → 都市映像`。
- 现有导航文字已确定为：首页、情报速递、角色介绍、世界全景、都市映像；无登录、充值、下载入口。
- 内容契约包含：`HeroConfig`、`NewsItem`、`Role`、`World`、`City`。新闻分为“做了什么 / 谁入职了 / 谁发牢骚了”。
- 当前首页生产实现 `HomePage.tsx` 只有全屏视频、`poster` 和遮罩；文件注释明确写着“无标题/副标语/CTA 按钮/滚动提示”。这与 `content-model.md` 中原先定义的 Slogan、CTA、滚动提示不一致，是正式设计前必须确认的产品决策点。
- 首屏视频路径为 `/assets/videos/home-video.mp4`，poster 当前使用 `/assets/cities/city-vision.png`；视频属性为 `autoplay muted loop playsInline`。
- 已有素材包括：三张角色立绘、三张世界场景图、一张都市愿景图、一段首页视频、logo，以及三张团队生活/工作照片素材。
- 现有官网和 Xiaomei Design System 都将 `#1d1d1d` 作为深色骨架色、`#50e5fb` 作为唯一品牌主强调色；粉色 `#fe5a95`、紫色 `#7958cb` 是有限语义/点缀色。
- 设计规则要求先做 UX 分析；元素必须服务任务；按钮、卡片、导航要有完整状态；键盘 focus-visible 可见；触控目标至少 44px；支持 `prefers-reduced-motion`。
- 现有 tokens 以 4px 为基础间距，圆角有 4/8/16/999px 四档，默认阴影为 none，主要字体是中文无衬线栈，工程元素可使用等宽字体。
- 现有角色页、世界页、都市页已经为“角色、场景、愿景”的视觉叙事提供了落点；首页不需要重新解释所有字段，而应完成入口和路线选择。
- 现有项目文档参考的是《异环》官网范式，但本报告不进行新的外部访问；有关该参考站的结论仅视为项目内既有分析记录。

### 0.2 建议/推断

- 首页的主要用户不是每天操作工具的内部成员，而是第一次访问的陌生访客、潜在合作方、关注团队的人，以及想了解成员角色的人。因此首页应优先完成“这是谁、如何工作、我应该看什么”的认知任务，而不是把首页做成真正的任务控制台。
- 首页应恢复至少一个可理解的品牌陈述和一个明确的下一步入口。纯视频可以建立氛围，但无法独立回答团队是什么、用户能获得什么信息、为什么继续浏览。
- “情报速递”可以作为可信度证明，但当前新闻样本主要是开发过程、入职和团队日常，不应在首屏假装成产品案例或商业成果。
- 角色与工作场景是当前最强的真实内容资产；首页应把它们作为“团队如何协同”的证据，而不是只把角色当装饰海报。
- 三个方向都可以复用当前五段信息架构，但首屏排序、内容密度和 CTA 语义不同。
- `#1d1d1d / #50e5fb` 应继续使用，但必须从“全站每处都发光”收敛为稳定的品牌骨架与聚焦色：深色负责沉浸和素材托底，青色只负责当前状态、主行动、路径提示和少量工程标记。
- 是否需要真实产品、客户、服务范围、招聘或联系方式，目前没有项目文件证据，不能直接写入首页。应列为后续内容采集或外部研究。

### 0.3 关键用户任务分析

| 用户 | 进入首页时的问题 | 首页必须支持的任务 | 成功信号 |
|---|---|---|---|
| 第一次访问的陌生访客 | 这是什么团队？“AI 工作室”具体意味着什么？ | 在首屏读懂身份与基本工作方式；选择继续看角色、情报或世界 | 10 秒内能说出团队名和至少一个浏览入口 |
| 潜在合作方/委托方（推断） | 团队是否可信、是否真的在做事？ | 快速找到产出动态、成员分工、工作环境证据 | 能进入情报或角色页，而不是只看完视频离开 |
| 对 AI 角色/世界观感兴趣的访客 | 角色是谁？世界观是否有连续性？ | 先看角色，再进入各自工作场景和愿景 | 角色与世界之间形成连续浏览路径 |
| 团队成员/熟人 | 最近做了什么？谁负责什么？ | 快速进入情报和角色 | 导航和 section 语义清楚，不需要猜图标 |
| 移动端访客 | 首屏是否加载、文字是否可读、如何继续？ | 在视频不可用、窄屏、减动效时仍能识别身份并操作 | 无视频也能完成首个导航操作 |

### 0.4 首页应解决的 UX 问题

1. **当前纯视频缺乏身份解释。** 视频回答“氛围是什么”，不回答“团队是谁”。建议保留视频，但叠加一句可检索的品牌陈述和工作方式摘要。
2. **下一步路径不明确。** 五个全屏 section 已存在，但首页没有 CTA/滚动提示。建议只保留一个主 CTA，避免把所有入口平铺成按钮墙；次级路径使用低干扰文字链接或导航。
3. **品牌叙事与真实证据断开。** 当前素材有角色、工位和新闻，建议建立“身份 → 组成 → 工作证据 → 愿景”的路径，而不是连续播放五张海报。
4. **内容模型与首页实现存在冲突。** `HeroConfig` 仍定义 slogan 和 CTA，但 `HomePage.tsx` 删除了这些内容。正式开发前必须决定“纯视频是否是有意的产品策略”；本报告推荐恢复最小文案层，而不是恢复复杂下载/平台入口。
5. **桌面全屏模式可能削弱移动阅读。** 五个全屏 section 与移动端内容高度有冲突风险，推荐首页首屏保留视觉舞台，但允许 section 内在移动端自然增长，不能强行把所有文字压进一屏。
6. **视频失败时的可用性未被首屏文案兜底。** poster 只能提供视觉，需为视频不可播放、慢加载和减动效用户保留语义内容与 CTA。

### 0.5 内容证据与缺口

**已确认内容资产：**

- 品牌：世界第一 AI 工作室。
- 成员：小黑 / 小优 / 小夜及其职位、简介、梦想。
- 工作环境：三张成员工作场景图和对应描述。
- 动态：工作成果、入职、牢骚三种类型，当前有静态兜底样本。
- 愿景：一张“未来都市”图及愿景文案。

**当前缺口：**

- 没有已确认的客户案例、产品目录、服务范围、合作方式、联系方式、招聘职位、团队规模、成果指标。
- 没有已确认的首页视频字幕、镜头时间轴、可读文字安全区或 poster 专用图片。
- 没有项目文件证明“AI 工作室”是对外提供什么具体服务。
- 以上内容若要进入首页，需内容负责人确认；相关竞品、行业定位和用户访谈属于“待外部研究”。

## 1. 三套首页方向总览

| 方向 | 主要解决的问题 | 叙事主轴 | 适合的访客状态 | 风险 |
|---|---|---|---|---|
| A. Studio Editorial | 团队身份模糊、品牌口号缺少可信语境 | 以编辑策展方式讲清团队与作品 | 想快速理解品牌、审美和团队组成的人 | 可能过于克制，弱化 AI 工作室的世界观与动态感 |
| B. Living AI World | 角色和场景素材没有形成连续体验 | 访客进入一个由角色、工位和愿景组成的工作室世界 | 对角色设定、视觉叙事和 AI 世界观感兴趣的人 | 可能像游戏官网，团队能力与真实工作证据被遮蔽 |
| C. Operational Intelligence | “工作室”没有被证明为真实协作系统 | 从任务、情报、角色职责和状态看团队如何运作 | 技术用户、潜在合作方、关心执行可信度的人 | 可能太像内部控制台，首次访问者理解成本高 |

## 2. 方向 A：Studio Editorial

### 2.1 UX 目标

**目标：**让首次访问者在 10 秒内理解“这是一个由明确角色组成、持续产出并有长期愿景的 AI 工作室”，并以低干扰路径进入角色、情报或世界内容。

**目标用户：**品牌访客、潜在合作方（推断）、对团队故事感兴趣的公众、希望快速扫读的移动访客。

**核心任务：**

1. 识别团队名称与定位。
2. 判断团队由谁组成、各自做什么。
3. 用一条真实动态或一个工作场景验证“不是只有口号”。
4. 选择继续阅读品牌故事、角色、情报或世界。

### 2.2 信息架构

推荐首页内容顺序：

1. **Identity**：品牌名 + 一句可验证范围内的工作方式陈述。
2. **Index**：三个成员以编辑目录/人物条目出现，链接到角色 section。
3. **Proof**：一条最新动态 + 一张工作场景图，链接到情报/世界 section。
4. **Manifesto**：团队愿景与都市映像，作为收束。
5. **Global navigation**：保持现有五项导航，不新增无内容依据的“服务/关于/招聘”。

它解决的是“先建立理解，再让用户选择深入”的问题。首页不承担展示所有详情的任务。

### 2.3 首屏结构

- 顶部：现有固定导航，logo 左、五项导航居中，右侧品牌字标可保留但降低干扰。
- 主舞台：保留全屏视频或 poster，视频上加深色可读性遮罩。
- 左下或左中：`世界第一 AI 工作室`，下方一行明确但不夸张的说明，例如“工程、运维与助理协作，把想法推进到可交付状态”（文案需内容确认；当前为建议/推断）。
- 主 CTA：`认识团队`，滚动到角色 section；次级文本入口：`查看最新动态`。
- 右下：非必需的章节索引或“01 / 05”，用于告诉用户还有内容，不与 CTA 争夺注意力。
- 视频无障碍替代：poster + 同一文案层，不依赖视频画面理解。

### 2.4 页面区块

1. **Brand opening**：身份、工作方式、认识团队。
2. **People index**：小黑 / 小优 / 小夜三项编辑式条目，展示职位和一句职责摘要。
3. **Selected signal**：最新一条情报，显示日期、类型、标题、作者；通过“查看情报”进入 `#news`。
4. **Working worlds**：三张工作场景横向索引，解决“成员如何工作”的理解问题。
5. **Future city**：使用 `city-vision.png` 作为愿景收束，避免把愿景误当现状成果。
6. **Footer**：保留团队署名和回到首页，补充明确的版权/联系内容前需确认。

### 2.5 视觉语言

- **色彩：**延续 `#1d1d1d` 和 `#50e5fb`。深色是内容底和沉浸框架，青色只用于标题小标、当前索引、CTA 描边/填充和焦点态。粉/紫仅保留情报类型语义，不用于大面积品牌背景。
- **字体：**正文使用现有中文无衬线栈；品牌展示标题可在单处使用宋体/衬线栈，制造编辑感，但正文和导航不混用。等宽字体仅用于日期、章节编号、类型标记。
- **版式：**12 列桌面网格，内容最大宽度 1200–1440px；首屏文案占 4–5 列，素材占 7–8 列；普通区块采用左对齐，避免所有内容居中造成阅读入口不清。
- **间距：**4px 基准；首屏内容块间 16/24px，主区块间至少 64px；移动端横向内边距 20px，区块间 48px。
- **圆角：**沉浸式视频/大图不加圆角；编辑条目使用 `4px` 或 `8px`；不使用大面积胶囊，避免从杂志目录变成 SaaS 标签墙。
- **阴影：**默认 none；悬浮项目用现有 `shadow-sm` 或细描边，不用厚重阴影，以保持纸面/画廊感。

### 2.6 动效

- 视频缓慢循环，禁止额外粒子和视差。
- 首屏文案在视频准备后淡入 300ms；滚动到区块时条目以 80ms stagger 进入。
- 人物/场景索引 hover 只改变描边、标题颜色和小幅位移，150ms。
- 点击 CTA 使用现有 section smooth scroll；`prefers-reduced-motion` 下直接定位。
- 轮播不自动播放，避免编辑阅读被打断；若复用现有新闻轮播，需在减动效和用户暂停时停播。

### 2.7 响应式

- 桌面 ≥ 1200px：视频全屏，文案固定在安全区，索引采用三列或横向目录。
- 平板 768–1199px：文案宽度收窄，人物条目改为两列/可横滑，避免文字覆盖视频主体。
- 手机 < 768px：首屏允许超过一屏高度，文案落在视频底部的独立深色内容带；主 CTA 触控区域 ≥ 44px；人物条目改为垂直列表；视频可降级为 poster。
- 矮屏横屏：优先保证导航、品牌名和 CTA 可见，取消装饰性章节编号。

### 2.8 素材使用

- `home-video.mp4`：首屏品牌氛围，必须提供 poster 和文字语义替代。
- `logo.png`：导航品牌识别。
- `roles/*.png`：人物目录/角色 section 入口，不在首屏全部大幅叠放，避免争夺主角。
- `worlds/*.png`：证明工作方式，使用裁切安全的横向索引。
- `cities/city-vision.png`：愿景收束；不得暗示这是当前办公地点。
- `team/life-*.png`：可作为“正在发生”的编辑选图；当前项目文档将其作为新闻轮播素材，具体内容归属需确认。
- 没有素材的案例/服务/招聘区域不创建视觉占位。

### 2.9 无障碍

- 首屏视频 `aria-hidden` 只适用于纯装饰视频，品牌文案必须在 DOM 中真实存在。
- 视频提供 poster、静音、暂停/降低动效机制；不依赖自动播放传达关键信息。
- H1 只保留一个，标题层级按 section 语义排列。
- CTA 使用动作文字，不用“了解更多”这种低信息量标签；键盘 focus-visible 对比度 ≥ 3:1。
- 图片 alt 描述内容功能，如“未来都市愿景图”，不重复装饰性文案。
- 文字对比度遵循 WCAG AA；在视频上通过局部遮罩保证，而非降低文字颜色。

### 2.10 风险与适用场景

**风险：**编辑式大留白会减少首屏信息吞吐；如果未来需要展示服务范围或案例，当前内容模型不够支持。衬线标题若过大可能削弱工程可信度。视频仍可能掩盖文字，需浏览器截图验证安全区。

**适用：**品牌优先、内容量有限、需要建立第一印象和信任的团队官网。适合当前真实资产最少、但角色与视觉素材较完整的阶段。

## 3. 方向 B：Living AI World

### 3.1 UX 目标

**目标：**把“AI 工作室”解释成一个有角色、有日常、有工作空间、有共同愿景的可探索世界，让访客先产生探索动机，再在探索过程中认识职责与工作证据。

**目标用户：**喜欢角色叙事和世界观的访客、已有角色兴趣的用户、团队成员/熟人、偏视觉体验的移动用户。

**核心任务：**

1. 进入工作室世界并理解三个角色不是独立海报，而是协作关系。
2. 从角色进入对应工作场景。
3. 通过新闻/情报感知世界正在变化。
4. 最后看到团队愿景。

### 3.2 信息架构

推荐路径：

1. **Portal**：首屏是“进入工作室”的入口，不解释全部内容。
2. **Cast**：三角色作为世界中的居民/职责节点。
3. **Spaces**：每人对应一个工作场景。
4. **Signals**：情报是世界中的实时事件，不是普通公告列表。
5. **Horizon**：都市映像作为世界边界和愿景。

该结构解决的是“静态素材如何变成可探索关系”的问题，但它把理解团队能力的任务放到了探索之后。

### 3.3 首屏结构

- 全屏视频作为工作室“入口场景”。
- 中央品牌名或短句，周围以三个低干扰节点标记小黑、小优、小夜；节点必须有文本标签，不只用装饰圆点。
- 主 CTA：`进入工作室`，进入角色 section。
- 次级路径：`查看当前情报`，进入 news。
- 场景提示可使用 `01 / 05` 或“角色 / 场景 / 情报 / 愿景”目录，避免让访客不知道还有什么。

### 3.4 页面区块

1. **Studio gate**：视频、品牌名、进入入口。
2. **Character constellation**：三角色横向/环形索引，每个节点明确职位和“负责什么”。
3. **Living desks**：三工作场景图，按角色切换，展示工作对象和动作，而不是只展示背景。
4. **Live signals**：新闻列表按时间线呈现，类型色承担事件分类。
5. **City horizon**：都市愿景图，用“未来目标”标签防止与现状混淆。
6. **Footer / return**：回到入口。

### 3.5 视觉语言

- **色彩：**以 `#1d1d1d` 为世界底色，`#50e5fb` 表示可探索节点、当前角色和路径连接；粉/紫分别绑定角色或情报语义时必须保持全站一致。避免把每个角色做成独立主题色，防止世界碎片化。
- **字体：**无衬线负责角色名称、说明；等宽字体负责世界坐标、时间、事件编号。展示标题可以使用现有无衬线大字，不建议装饰字体，否则会让角色世界盖过团队信息。
- **版式：**大图全屏 + 关系索引。桌面使用 12 列网格，左侧保留角色导航，右侧保留主体视觉；移动端改为顶部横向角色选择 + 底部信息区，延续现有 RolesPage 结构。
- **间距：**主体节点之间至少 24px；触控节点视觉可小，但实际按钮区域 ≥ 44px；文本与视频亮部之间留 24–32px。
- **圆角：**大图无圆角；角色节点 8px；状态徽章可使用 full；不要给每个场景套卡片，避免“卡片里又套世界”。
- **阴影：**用细描边和局部深色遮罩建立层级；仅当前节点允许 `shadow-accent`，其余无阴影。

### 3.6 动效

- 首屏视频循环；入口点击后短暂淡出并进入角色 section。
- 角色切换采用 500–900ms cross-fade，匹配现有角色页的既有叙事和项目内参考分析。
- 场景切换只做图片交叉淡化和 caption 更新，不做视差；当前节点有 150ms 描边反馈。
- 情报按时间线从下方轻微进入；自动轮播默认暂停或提供暂停按钮。
- 动效减少模式下静态 poster、直接显示当前角色和场景。

### 3.7 响应式

- 桌面：角色导航左侧竖排，主体背景和立绘形成右侧主角；信息位于左下/中左。
- 平板：角色导航压缩为顶部横向 tab，信息区宽度至少 45ch 以内。
- 手机：沿用现有角色页思路，顶部横排头像导航，底部深色信息面板；“展开介绍”必须是明确按钮，展开后不能遮挡角色名称。
- 手机视频默认降低尺寸/使用 poster，保证角色信息可读；世界场景图使用 `object-position` 配置而不是简单居中裁切。

### 3.8 素材使用

- `home-video.mp4` 是“入口场景”，不是背景装饰；视频画面中的三角色顺序需与内容文案一致，当前没有镜头时间轴，待内容确认。
- `role-xiaohei.png`、`role-xiaoyou.png`、`role-xiaoye.png` 用于角色节点和角色 section 主视图。
- `world-xiaohei.png`、`world-xiaoyou.png`、`world-xiaoye.png` 分别绑定角色，形成“人 → 空间”关系。
- `city-vision.png` 是世界尽头/愿景，不标成当前场景。
- `team/life-*` 可作为情报事件配图，但项目现有新闻数据未包含图片字段，需扩展内容模型前先确认，不在本轮实现中假定。

### 3.9 无障碍

- 所有探索节点都必须有可读文本、按钮名称和 `aria-current`；不能只依赖位置或颜色。
- 角色切换时用 `aria-live="polite"` 更新当前角色职位，避免整个背景图重复朗读。
- 背景图 alt 说明其信息功能；装饰性世界氛围图使用空 alt 并确保文本已说明内容。
- 轮播提供暂停、上一张、下一张和当前项状态；键盘可操作。
- 颜色不是唯一状态表示：当前角色需同时有文字/边框/`aria-current`。
- 支持 reduced motion，禁用交叉淡化和自动播放。

### 3.10 风险与适用场景

**风险：**叙事容易滑向游戏官网，访客记住角色却不理解团队的真实工作；“生活”内容目前主要是设计推断，不能凭空增加日常事件；视频与静态图的角色一致性需要人工视觉 QA。项目当前没有多场景城市素材，世界规模有限。

**适用：**品牌希望突出角色人格与世界观、素材驱动、访客停留时间较长的展示型首页。若团队后续计划发展角色 IP，此方向具有延展性。

## 4. 方向 C：Operational Intelligence

### 4.1 UX 目标

**目标：**把团队的“工程、运维、助理协作”变成可扫读的运营信号，让访客用事实结构理解工作室如何推进任务、如何分工、如何保持可靠。

**目标用户：**技术访客、潜在合作方（推断）、内部成员、关注执行过程和持续交付的人。

**核心任务：**

1. 快速看到团队当前做了什么。
2. 通过成员职责理解谁负责哪类问题。
3. 通过工作场景感知系统/环境分工。
4. 进入完整情报列表，获取更多上下文。

### 4.2 信息架构

推荐首页顺序：

1. **Status headline**：团队身份 + 当前工作状态，但只显示项目文件可证实的状态。
2. **Signals**：最新 3 条情报，按类型/日期扫读。
3. **Operators**：三个成员和职责，强调协作链路。
4. **Workspaces**：三个工作场景，说明各自工作对象。
5. **Mission**：都市愿景。

它解决的是“口号如何被行动证明”的问题，首屏任务更接近可信度检查，而不是情绪沉浸。

### 4.3 首屏结构

- 深色视频作为右侧/背景氛围，左侧为高对比信息列。
- 品牌名与一条状态式陈述，例如“工程、运维与助理，持续把事情推进到下一步”（建议/推断，需确认）。
- 下方显示 3 个轻量指标/信号：`3 个角色`、`3 个工作空间`、`最新动态`。这些数字可以从项目现有数据推导，但“持续”或“已完成”不能无证据使用。
- 主 CTA：`查看最新动态`，因为 C 方向的主要价值是证据；次级入口为 `认识团队`。
- 不设计真实监控指标、在线率、部署次数或 SLA 卡片，项目没有这些数据。

### 4.4 页面区块

1. **Operational hero**：身份、工作方式、情报入口。
2. **Latest signals**：复用 NewsItem 的类型、标题、日期、作者，最多 3 条；提供“查看全部情报”。
3. **Role matrix**：成员、职位、职责关键词；不要虚构权限或绩效指标。
4. **Workspace map**：三张工作场景图与工作对象说明。
5. **Mission horizon**：都市愿景图，明确标记为愿景。
6. **Footer**：署名与回到首页。

### 4.5 视觉语言

- **色彩：**`#1d1d1d` 作为控制台式底色，`#50e5fb` 只表示链接、当前状态和主要行动；情报类别沿用青/粉/紫，但每个类别必须有文字标签。避免大面积渐变或霓虹光晕，否则“状态”会和装饰混淆。
- **字体：**正文中文无衬线；日期、ID、章节编号使用等宽字体；标题用无衬线 600，避免过多衬线导致工具感下降。
- **版式：**12 列网格，首屏左 5 列信息，右 7 列视频；后续区块采用高密度但有层级的列表/矩阵。桌面可两列，手机单列。
- **间距：**列表行高最少 44px；信息组内 8–16px，区块间 48–64px；卡片内容标准内边距 16 或 24px，统一使用一个选择。
- **圆角：**列表和面板使用 4–8px；大图无圆角；状态标签使用 full；不将整个页面拆成多层浮动卡片。
- **阴影：**默认 none；下拉/弹层使用 `shadow-md`；焦点或当前状态可用 `shadow-accent`，不做全局光晕。

### 4.6 动效

- 首屏视频低速循环，首屏数据区静态显示，避免自动跳动影响扫读。
- 最新情报加载状态用明确的 skeleton/文本，失败状态给出“暂时无法加载，查看已缓存内容”的可理解反馈；当前客户端已有 4 秒超时和静态兜底，设计上应暴露状态而非空白。
- Tab 切换 150–200ms；列表 hover 只改行底线/文字色。
- 工作场景 hover 用轻微裁切位移或描边，不用视差。
- reduced motion 下停止视频或使用 poster，所有列表直接呈现。

### 4.7 响应式

- 桌面：信息列和视频并排；最新情报三行可见，保证首屏有事实证据。
- 平板：视频上方或右侧缩小，信息列先出现；三条情报改为横向滚动或单列。
- 手机：首屏按“品牌 → 证据 → CTA”纵向排列，视频不遮挡文字；指标改为三行文本而非小卡片；情报列表保持 44px 以上行高。
- 窄屏/低带宽：poster 优先，所有内容不依赖视频；图片使用合适尺寸和 lazy loading。

### 4.8 素材使用

- `home-video.mp4` 提供氛围，但首屏信息价值来自文字与最新情报，不让视频承担证明任务。
- `role-*.png` 用于角色矩阵，裁切为头像或人物缩略，不丢失 alt。
- `world-*.png` 用于“工作对象/工作空间”区块，横图优先。
- `city-vision.png` 作为 Mission 区块，并显示“愿景/未来”语义。
- 新闻轮播生活照可作为情报的视觉辅助，但现有 `NewsItem` 没有 image 字段，除非内容模型正式扩展，否则只使用已有 `NEWS_CAROUSEL_SLIDES` 机制并明确其独立于新闻事实。

### 4.9 无障碍

- 数据/信号同时显示文字和类型，不依赖颜色；日期使用 `<time>`，列表使用语义列表或 article。
- 加载、错误、空状态明确，并可被屏幕阅读器感知；静态兜底内容若继续保留，应说明“显示缓存内容”而非假装实时。
- 键盘能够完成 Tab 切换、场景选择和 CTA；focus-visible 边框不能只使用低对比青色。
- 最高优先级 CTA 每屏只有一个；指标不是按钮时不应伪装成可点击卡片。
- 视频必须可暂停/降级；自动播放不能制造闪烁，避免快速亮暗镜头。

### 4.10 风险与适用场景

**风险：**当前数据量和字段不足以支撑真正的运营智能首页；如果使用“在线、稳定、完成率、监控”等词，会把推断伪装成事实。高密度首屏不适合普通访客和纯品牌访问。当前项目阶段边界也明确暂时不要复杂 UI，因此不要把它设计成真实控制台。

**适用：**团队希望强调工程可信度、持续交付、协作链路，且未来能提供真实项目状态/案例数据时。当前更适合作为“轻量 operational editorial”而不是完整仪表盘。

## 5. 推荐方向

### 5.1 推荐：A. Studio Editorial，吸收 C 的证据模块与 B 的角色/场景关系

推荐不是把 A、B、C 做成混合视觉，而是采用 A 的首页任务与版式作为主方向，选择性吸收：

- 从 C 借用“最新情报作为可信度证据”的内容逻辑，但不使用虚构的运营指标。
- 从 B 借用“角色 → 工作场景”的内容关系，但不把官网包装成游戏世界入口。
- 保留当前全站五段导航与深链兼容，不新增项目文件没有支撑的业务入口。

### 5.2 选择依据

1. **最匹配当前证据量。** A 能用现有品牌、角色、新闻、场景和愿景完成完整首页；C 需要更多真实状态数据，B 需要更多世界观/事件内容。
2. **最先解决首次访问任务。** A 先回答“是谁”，再让用户选择“看谁/看什么”，符合 Xiaomei 原则中的信息层级和用户任务优先。
3. **保留品牌资产连续性。** 深色大图、视频、青色强调、全屏 section、角色导航都可延续，不需要用新的视觉主题覆盖现有官网。
4. **降低误导风险。** 不会把“AI 工作室”过早表述成已具备客户案例或运营指标，也不会把愿景图误导为现状。
5. **适合后续扩展。** 如果未来有案例和服务内容，编辑式结构可新增“Selected work”；如果未来角色世界观增强，也可在人物/场景区块扩展，而不必重做首屏骨架。
6. **更适合移动端。** A 可以将首屏从强制全屏改为视觉舞台 + 可读内容带，避免 B 的复杂交互和 C 的高密度在小屏上失控。

### 5.3 颜色结论：继续使用，但重新定义职责

**已确认：**项目 style-guide、frontend tokens 和 Xiaomei tokens 都以 `#1d1d1d / #50e5fb` 为官网/团队设计语言基线。

**建议：**继续保留，不改品牌识别；但是：

- `#1d1d1d`：全站深色背景、导航实底、视频/图片后的稳定底色。
- `#50e5fb`：唯一品牌动作色，用于当前导航、主 CTA、章节索引、焦点环和少量关键标记。
- `#7ce3f2`：深色背景上的次级文字强调，不能代替正文对比度。
- `#fe5a95 / #7958cb`：仅用于新闻类型或内容分类；不能让角色/页面各自换一套品牌色。
- 不把青色作为大面积渐变、全局 text-shadow 或持续光晕；项目内参考分析已经确认参考导航的 active 是换色而非扩散光晕。
- 正式实现前必须用浏览器和对比度工具验证视频各帧上的文字安全区；本报告不把颜色对比判断当作已完成 QA。

## 6. 推荐方向完整 DESIGN_SPEC

### 6.1 Page

- **Page name：**首页 / Studio Editorial opening。
- **Route：**`/`，保留 `#home`；现有旧路径与 hash 深链机制继续有效。
- **Primary goal：**在视觉沉浸中快速建立团队身份，并把访客引向角色或情报。
- **Secondary goals：**让访客理解“工程、运维、助理”是协作结构；为后续世界/都市内容提供上下文。
- **Primary CTA：**`认识团队` → `#roles`。
- **Secondary action：**`查看最新动态` → `#news`，使用低干扰文字链接，不与主 CTA 同层级。
- **Content density：**低到中密度。首屏只显示品牌身份、工作方式摘要、两个路径；详细 bio、新闻正文和场景描述留在后续 section。
- **Out of scope：**登录、下载、充值、真实监控指标、客户案例、招聘、联系方式、服务承诺，除非内容负责人补充并确认数据。

### 6.2 Viewport

设计验收至少覆盖以下视口：

- Desktop wide：1440 × 900、1920 × 1080。
- Tablet landscape：1024 × 768。
- Tablet portrait：768 × 1024。
- Mobile：390 × 844、360 × 800。
- Mobile landscape / short viewport：844 × 390、1280 × 600。

约束：

- 不以固定设计稿缩放取代响应式布局。
- 首屏视频/图像保持稳定裁切，文字始终位于可读安全区。
- 手机首屏允许内容高度超过视口；不能为了保持“全屏”而裁掉品牌名或 CTA。
- 所有操作目标最小 44 × 44px；正文默认不低于 16px。

### 6.3 Sections

#### Section 0：Loading / transition（保留并收敛）

- **Purpose：**给视频和首屏资源一个短暂初始化时刻，延续现有品牌加载基因。
- **Content：**品牌名、`AI TEAM · EST. 2026`、简短进度反馈。
- **Behavior：**不等待无限网络资源；最长时间有上限；加载完成淡出。
- **Decision:** 延续现有 `LoadingOverlay` 的品牌识别，但 reduced motion 下应静态显示并尽快结束。当前加载层 `aria-hidden`，关键品牌信息必须仍存在于页面主体。

#### Section 1：Hero / Brand opening

- **Background:** `home-video.mp4`，poster 为明确适配首屏的静态图；当前 `city-vision.png` 可暂作 fallback，但建议正式设计时增加/确认专用 poster。
- **Overlay:** 顶部轻遮罩保证导航区，文字区域局部深色渐变，避免整屏压黑。
- **Content:**
  - H1：`世界第一 AI 工作室`。
  - Supporting copy：一句说明协作方式；当前建议文案“工程、运维与助理协作，把想法推进到可交付状态”，需内容确认。
  - Primary CTA：`认识团队`。
  - Secondary link：`查看最新动态`。
  - Optional index：`01 / 05` 或“品牌 / 情报 / 角色 / 世界 / 愿景”，仅作为路径提示。
- **Problem solved:** 解决当前纯视频无法识别身份和下一步的问题。

#### Section 2：Team index（可落在首页后续内容流或与 `#roles` 视觉衔接）

- **Purpose:** 用三个真实角色说明团队结构。
- **Content:** 姓名、职位、职责一句话、头像；点击进入角色 section，并可在角色 section 查看个人梦想。
- **Layout:** 桌面三列编辑条目；手机单列。
- **Problem solved:** 将“AI 工作室”从抽象口号转为可理解的职责组合。

#### Section 3：Selected signal

- **Purpose:** 用一条或三条最新 `NewsItem` 建立“正在做事”的证据。
- **Content:** 类型、标题、日期、作者；默认不展开长正文。
- **Interaction:** 点击进入 `#news`，不在首页嵌套完整 Tab 系统。
- **States:** loading、success、empty、fallback/error。
- **Problem solved:** 防止首页只剩品牌自述，没有当前动态。

#### Section 4：Working worlds

- **Purpose:** 展示成员工作空间，连接角色与工作方式。
- **Content:** 三张 `World` 图、owner、name、description 摘要。
- **Interaction:** 点击跳转到 `#world`，或在首页仅做静态索引，避免重复构建第二套场景轮播。
- **Problem solved:** 解释每个角色做什么、工作对象是什么。

#### Section 5：Mission horizon

- **Purpose:** 收束愿景，而非伪装成已实现成果。
- **Content:** `City` title、description、明确的“愿景 / NEXT”语义。
- **Asset:** `city-vision.png`。
- **Problem solved:** 给品牌叙事方向感，同时与当前工作证据区分。

#### Section 6：Footer

- **Confirmed:** 现有团队署名和回到顶部。

### 6.4 Components

以下为 DESIGN_SPEC 层面的组件职责，不要求本轮立即新增或修改代码：

- **GlobalNav**：logo、五个 section 入口、当前 section、键盘导航；沿用现有 `NavBar` 语义。
- **HeroMedia**：视频、poster、播放/降级策略、局部遮罩；视频为装饰媒体，不承担唯一语义。
- **HeroCopy**：H1、supporting copy、primary CTA、secondary link；每屏一个 primary CTA。
- **SectionIndex**：章节/section 数字或文字索引；只提供位置感，不替代导航。
- **EditorialPeopleList**：三位成员条目；支持 default/hover/focus/active/加载/空状态。
- **SignalPreview**：最新情报预览；类型徽章、标题、日期、作者、进入情报动作。
- **WorldPreview**：工作场景索引；图片、owner、名称、摘要、进入世界动作。
- **MissionPreview**：愿景图与说明；明确愿景语义。
- **PrimaryButton / TextLink**：主 CTA 和次级入口；使用动作文案。
- **LoadingState / ErrorState / EmptyState**：所有 API 依赖区域必须有可读状态。
- **FocusRing**：统一 `focus-visible` 视觉，不让各页面自行定义。

组件规则：

- 不嵌套卡片；大图区域是舞台，不是卡片。
- 文案组件不把关键文本画进图片。
- 图标只在确实有图标语义的按钮中使用；熟悉的箭头等可以是 icon，但必须有可访问名称。
- 组件状态至少定义 default / hover / active / focus / disabled / loading / error；首页若没有 disabled，应说明该组件不适用。

### 6.5 States

#### 页面级

- **Initial loading：**加载层显示，主体已有可读 DOM；不让用户无限等待。
- **Ready with video：**视频播放，文案和 CTA 可用。
- **Ready without video：**poster 或深色背景 + 完整文案，功能不下降。
- **Reduced motion：**视频可暂停或不自动播放；移除淡入、滚动吸附动画和轮播自动切换。
- **Keyboard focus：**CTA、导航、人物、场景入口有清晰高对比 focus ring。

#### 内容级

- **News loading：**保留结构占位并说明正在读取动态。
- **News success：**显示最新 1–3 条，日期和类型可扫读。
- **News empty：**显示“暂时没有新的动态”，提供去角色/世界的下一步，不留空白。
- **News API failure with fallback：**若沿用当前静态兜底，界面应能区分“缓存/项目内内容”与实时数据，避免虚假实时感。
- **Image loading/error：**图片区域保留稳定尺寸；失败时显示对应名称和中性色占位，不让布局跳动。
- **Video blocked:** poster + 文案继续工作；不显示播放器错误给普通访客。

#### 交互状态

- Navigation：normal 灰、hover 白、active 青、focus-visible 高对比环。
- Primary CTA：normal 青色实心/高对比深字，hover 轻微亮度变化，active 位置反馈，focus-visible 外环，disabled 仅用于真实不可用时。
- Editorial item：normal 无阴影、hover 细线/标题色变化、active 当前入口有青色标记。
- Motion：所有状态变化 150–300ms；不使用持续闪烁。

### 6.7 Interactions

1. **导航进入：**点击 `认识团队` 调用现有 section 导航机制，更新 hash 和 active 导航；不新增第二套路由。
2. **情报入口：**点击 `查看最新动态` 进入 `#news`；焦点和 hover 必须可区分。
3. **滚动：**桌面保留 section scroll-snap 叙事；推荐评估是否仅对 section 外壳 snap、section 内内容允许自然滚动，尤其是移动端。
4. **视频：**`autoplay muted loop playsInline` 可以保留为默认，但提供静音、不依赖视频的 poster/文案路径；减动效用户不应被迫看循环动画。
5. **加载：**现有 1.6 秒左右定时淡出可保留作为视觉机制，但正式实现应以资源状态和超时为依据；不得因为视频网络问题卡死。
6. **People/World preview：**点击整个可识别条目进入对应 section；若条目不是按钮，使用链接语义，不做不可访问的 div click。
7. **News preview：**不在首页打开复杂弹窗；进入 `#news` 后使用现有 Tab 和列表。
8. **Auto-rotation：**首页不自动轮播人物/场景；情报轮播若保留，提供暂停并在 reduced motion 下停用。
9. **Keyboard:**Tab 顺序为导航 → H1/supporting copy → primary CTA → secondary link → 首页可交互预览 → footer；装饰视频和背景图不进入 tab 顺序。
10. **Hash/back navigation：**继续尊重现有 `#home/#news/#roles/#world/#city` 和浏览器前进后退。

### 6.8 Responsive

#### Desktop ≥ 1200px

- 固定实底导航，高度沿用现有 `--nav-height`；logo、导航、右侧品牌字标不互相覆盖。
- Hero 使用全屏视频，文案位于左侧/左下安全区；内容最大宽度 1200–1440px。
- 角色/场景预览使用 3 列编辑网格；情报预览为左文本、右图片或单条重点信号，取决于真实内容量。
- section 间保留现有全屏叙事，但首页新增内容不能压缩到不可读。

#### Tablet 768–1199px

- 导航可横向滚动，但当前项必须始终可见；logo 不与导航重叠。
- Hero 文案宽度不超过屏幕 70%，避免覆盖视频主体；CTA 与副链接上下排列。
- 人物/场景预览改为两列或横向 scroll，实际按钮面积 ≥ 44px。
- 情报预览减少到 1–2 条，保留“查看全部”。

#### Mobile < 768px

- 首屏结构为“视频/poster 舞台 → 深色文案带 → CTA”，不把文字直接压在复杂画面上。
- H1 允许两行，行高 1.1–1.2；不使用负字距或 viewport 直接缩放字号。
- 主 CTA 满宽或至少 44px 高；次级入口用文字链接，不做两个同权重实心按钮。
- 人物/场景条目单列；图片使用固定 aspect-ratio，防止加载导致布局跳动。
- 新闻预览显示一条重点，日期使用等宽字体并保持可读；完整列表在 `#news`。
- safe-area inset 纳入底部内容和 footer。

#### Reduced motion / low bandwidth

- `prefers-reduced-motion: reduce`：停用 loading 波浪、淡入、smooth scroll、自动轮播；视频可暂停或换 poster。
- 视频不支持时：深色背景 + poster + 完整 HeroCopy + CTA。
- 图片加载中：保持固定舞台比例和文本占位；图片失败不影响导航。

### 6.10 Accessibility

- **语义结构：**页面只有一个 H1；各区块使用 H2；人物、动态、工作场景使用 article/list 语义。
- **视频：**视频作为装饰媒体时 `aria-hidden="true"` 或空 accessible name；关键品牌信息放在真实文本；提供 poster 和停用路径。若视频包含关键非装饰信息，需补字幕/文字描述后再决定是否隐藏。
- **图片：**人物 alt 格式为“姓名，职位”；场景 alt 格式为“姓名的工作场景：场景名”；愿景 alt 明确“未来都市愿景图”。纯背景装饰使用空 alt。
- **对比度：**正文与背景 ≥ 4.5:1；大字号至少 3:1；视频背景上的文本通过局部遮罩和安全区实现，不能只依赖阴影。实际色值需用 axe/对比度工具验证。
- **键盘：**所有导航、CTA、预览入口、轮播控制均可 Tab/Enter/Space；focus-visible 使用清晰轮廓，不与背景混淆。
- **触控：**所有移动端操作区域 ≥ 44px；相邻按钮有至少 8px 间距，避免误触。
- **动态内容：**情报加载/错误/空状态通过 `aria-live="polite"` 适度通告；不在每次图片轮播时重复朗读整个页面。
- **运动：**遵循 `prefers-reduced-motion`；自动播放、smooth scroll、fade 和 stagger 都有静态替代。
- **语言：**页面主语言中文；英文 kicker/日期只能作为辅助，不让英文标签承担唯一语义。
- **焦点顺序：**视觉顺序和 DOM 顺序一致；不使用大量绝对定位让键盘路径跳跃。

### 6.12 Implementation Notes

> 本节是交给实现方的设计约束，不代表本轮已修改代码。

1. 继续使用现有 `SECTIONS`、hash 深链和 `scrollToSection`；首页 CTA 不应另建 React Router 路径。
2. 在正式实现前先解决 `content-model.md` 与 `HomePage.tsx` 的冲突：推荐恢复最小 `slogan + sloganSub + ctaText`，不恢复参考站的登录/下载/充值入口。

4. `HeroMedia` 应有 `poster`、固定容器尺寸、加载失败和 `prefers-reduced-motion` 路径；不要因为视频加载阻塞整个首页。
5. 对现有 `fetchNews` 的 timeout/fallback 行为做设计暴露：如果显示 fallback，增加可理解的状态语义；不要在 UI 里写“实时”而数据实际是静态兜底。

7. 不新增真实运营指标、服务卡片、客户案例、招聘或联系表单，除非有内容来源和验收标准。
8. 大图使用稳定的 `aspect-ratio`、`object-fit` 和明确 `object-position`；开发后必须在 1440、1920、390、360 和矮屏视口检查裁切与文字重叠。
9. 不使用页面层的任意颜色、任意间距或新圆角；优先复用 `tokens.css` 和 Xiaomei tokens。若必须新增 token，按 Design System README 的四问写入设计系统文档，而不是只写 CSS。

12. 动效实现必须有 reduced-motion 分支；自动轮播需要暂停机制，首页首屏不自动切换多张内容。
13. 图片 alt、按钮 aria-label、`aria-current`、tablist 状态和错误/空状态需在实现测试中覆盖。
14. 正式开发完成后进行浏览器 Visual QA：桌面/移动截图、视频 poster fallback、文字对比度、键盘路径、焦点可见性、图片加载失败和 reduced-motion。
15. “待外部研究”清单：真实目标访客访谈、是否对外承接项目、竞品/同行官网对比、品牌语气验证、首页文案测试、视频镜头安全区和真实设备性能。没有完成这些研究前，不把 A 的推荐文案写成既定品牌事实。

## 7. 设计验收清单

### UX

- [ ] 首屏 10 秒内能识别团队名称与基本工作方式。
- [ ] 首屏只有一个清晰 primary CTA，且下一步可预测。
- [ ] 角色、情报、工作场景、愿景之间形成明确路径。
- [ ] 没有使用项目文件无法证明的客户、服务、指标或招聘承诺。
- [ ] 视频不可播放时仍能完成核心浏览任务。
- [ ] 移动端不需要理解全屏滚动机制才能继续。

### Visual

- [ ] `#1d1d1d / #50e5fb` 延续且职责清楚，不被大面积 glow 稀释。
- [ ] 视频/大图是主视觉，不被卡片和文案遮挡到无法识别。
- [ ] 文案安全区在 1440×900、1920×1080、390×844、360×800 均成立。
- [ ] 间距是 4px 基准，圆角和阴影复用 token。
- [ ] 不出现卡片嵌套、装饰性渐变 orb、无语义的粒子或视差。
- [ ] 中文字体和字重建立清晰层级，正文不使用装饰字体。

### Accessibility

- [ ] H1/H2 结构正确，关键文本在 DOM。
- [ ] 所有操作有键盘路径和可见 focus。
- [ ] 触控目标 ≥ 44px。
- [ ] 正文对比度达到 WCAG AA，视频背景经过实际检查。
- [ ] 图片 alt、视频 poster、加载/错误/空状态齐全。
- [ ] reduced motion 下没有强制动画或自动轮播。

## 8. 最终结论

当前项目最有价值的连续性不是“把首页做得更像某个外部网站”，而是把现有深色视频、青色品牌、角色、工位、情报和愿景这些已存在资产组织成一条可理解的访客路径。推荐 **Studio Editorial** 作为主方向：它先完成身份与导航任务，再用 C 的真实动态证据和 B 的角色—场景关系增加深度；同时保持 `#1d1d1d / #50e5fb`，但将青色从装饰光效收敛为品牌动作色。正式设计前最重要的待决策项是：确认首页是否恢复最小 Slogan/CTA 文案层，以及补充视频 poster、安全区和首页 supporting copy 的内容事实。
