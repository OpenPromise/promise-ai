# Promise AI 官网整站重设计规范

## DESIGN_SPEC

> 文档状态：整站重设计提案，供产品、内容、工程和视觉实现共同使用
>
> 事实边界：本稿只依据项目已提供的成员、资产和能力信息；未访问互联网，也未声称完成竞品研究。任何尚未被项目确认的内容均标记为“待内容确认”或“待外部研究”。本稿不修改生产代码。
>
> 核心判断：官网不应再是角色海报的连续播放，也不应伪装成已有客户、SLA 或实时运营数据的 SaaS 控制台。它应该是一个“可观察的 Agent 工作系统”：访客先理解工作单元，再沿证据查看角色、任务链、情报和愿景。

---

## 0. 官网真正要解决的三个问题

### 问题一：第一次访问者如何理解这不是普通角色展示页

首屏必须在不依赖视频、不依赖角色设定背景的情况下回答三件事：

1. Promise AI 是一个什么组织：一个由 AI Agent 组成的工作室。
2. Agent 不是四张拟人海报，而是有职责、工具、记忆和调度关系的工作单元。
3. 访客接下来能看什么：正在发生的工作证据、角色如何协作、系统如何运转。

因此首屏主语从“某个角色是谁”改为“一个任务如何在团队中被推进”。角色立绘仍是识别资产，但不再承担品牌解释。

**首屏验收标准：**陌生访客阅读 10 秒后，能复述“这是 AI Agent 团队/工作室”，并能指出一个进入工作证据的入口。

### 问题二：如何证明这些 AI 角色真的在工作

不能用“智能”“领先”“持续在线”等无证据的形容词证明。官网只展示项目已有的真实能力和真实内容资产：

- AI Agent 如何接收任务、调用工具、返回结果；
- 记忆如何让后续任务保留上下文；
- 小夜如何做中枢、调度并把工作交给小黑、小优、小美；
- 工程、运维、设计子代理分别负责什么；
- 情报速递中已经确认的工作、入职和团队动态；
- 角色与其工位/工作世界的对应关系。

证明形式应是“任务切片”和“事件记录”，不是伪造的数字指标。每个证据单元必须有来源、日期、角色和状态；没有数据时宁可展示空状态，也不做模拟在线率、完成率、客户案例或监控图。

### 问题三：如何让访客愿意继续探索或联系团队

继续探索的动力来自清晰的路径，而不是无限滚动和自动播放：

- 想知道“现在做了什么”进入「情报」；
- 想知道“谁负责什么”进入「团队」；
- 想知道“任务怎么被推进”进入「系统」；
- 想知道“这群 Agent 想去哪里”进入「世界」；
- 想进一步沟通时进入「下一步」，但在联系方式和合作模式未确认前只展示透明的待确认状态。

**联系策略：**不捏造邮箱、客户入口、服务目录或预约流程。先提供一个明确但诚实的 `联系团队` 位置，页面正文标记“联系方式待内容确认”；该入口可先承载内容负责人待补的联系模块，不让访客误以为表单已经可用。

## 1. Brand Thesis

### 1.1 设计方向

# **任务现场：Taskroom / 任务现场**

英文名：**Taskroom**

一句话定位：

> **Promise AI 是一个把任务交给 Agent、让工具产生结果、让记忆和调度把工作继续推进的 AI 工作室。**

“任务现场”不是内部控制台的公开版，也不是虚构的数字城市。它是一种网站叙事模型：每一个页面都围绕一个可观察的工作事实组织内容；角色是工作节点，世界是工作上下文，情报是时间证据，系统是关系图。

### 1.2 为什么比三个旧方向更适合

#### 比 Studio Editorial 更适合

Studio Editorial 的问题不是审美，而是它把“编辑呈现”当成了信息架构。大标题、细线和留白可以提升气质，却不能单独解释 Agent 的执行链。当前页面甚至以小美个人定位为主，容易让访客误判为设计师个人介绍页。Taskroom 把编辑能力降为呈现层，把“任务、角色、工具、结果”提升为内容骨架，可信度和品牌感同时成立。

#### 比 Living AI World 更适合

Living AI World 适合角色 IP 或游戏式探索，但当前真实资产不足以支持一个持续扩张的世界模型。它会让访客先记住场景和人设，再猜团队是否真的工作。Taskroom 保留世界/工位图作为上下文证据，同时明确标注“工作空间”和“愿景”，不把官网包装成游戏官网。

#### 比 Operational Intelligence 更适合

Operational Intelligence 能表达工程感，但容易制造“已经有成熟运营平台”的假象。现有事实支持 Agent、工具执行、记忆、调度和微信通道，不支持客户数、SLA、吞吐量、在线率或完成率仪表盘。Taskroom 借用可观察性和事件流的表达方式，但每个状态都绑定真实内容，不发明指标。

### 1.3 必须删除、保留、重新解释

#### 必须删除

- 当前 Studio Editorial 的“小美个人主页”式首页主叙事；小美是团队成员，不是官网主角。
- 纯视频首屏及“看完氛围就算理解”的假设。
- 五个全屏 section 作为唯一信息架构；移动端不再强制 scroll-snap。
- 没有内容依据的客户案例、服务承诺、营收、SLA、在线状态、团队规模、招聘职位、预约表单。
- 大面积渐变、霓虹光晕、装饰粒子、无语义的悬浮节点和把世界图当背景 wallpaper 的用法。
- 角色按“性格海报”并列却没有职责、上下游和工作产物的展示方式。
- `了解更多`、`进入世界` 这类无法说明后果的 CTA 文案。

#### 必须保留

- 小黑、小优、小夜、小美的现有成员事实和角色立绘。
- `home-video.mp4`、世界/工位图、都市愿景图和情报速递资产。
- “小夜是私人助理/中枢”“小黑是工程师”“小优是运维”“小美是产品/UI/视觉设计师”的角色关系。
- Agent、工具执行、记忆、任务调度、微信通道、工程/运维/设计子代理这些真实能力。
- 情报速递作为持续内容入口，但改变其呈现为证据日志，而非普通新闻轮播。
- 深色背景作为素材舞台、等宽字体作为事件标记、有限的青色强调作为路径/状态语言。

#### 必须重新解释

- **角色立绘：**从主视觉海报改为“执行节点头像/身份索引”，点击后查看职责、工具边界、工作场景和已确认动态。
- **世界/工位图：**从世界观插画改为“工作上下文”，说明该角色面对什么类型的工作；都市图明确为未来愿景，不是当前办公地点。
- **首页视频：**从品牌主叙事改为可暂停的“现场片段”，为理解提供氛围，不承担事实证明。
- **情报速递：**从内容轮播改为带类型、日期、作者、上下文的事件记录；“工作/入职/牢骚”保留为真实内容分类，不伪装成产品指标。
- **小夜：**从“可爱助理”重新解释为系统中的路由与上下文节点；她的视觉人格服务于“理解任务如何被接住”。
- **未来都市：**从终极大背景改为“尚未抵达的方向”，与当前能力事实严格分层。

## 2. Audience

### 2.1 主要访客

| 访客 | 认知任务 | 首要入口 | 成功信号 |
|---|---|---|---|
| 第一次访问者 | 判断这是什么组织和 Agent 是否真的工作 | 首页 → 工作方式 | 能说出“Agent 工作室”并找到一个证据 |
| 技术/产品访客 | 理解 Agent、工具、记忆、调度之间的关系 | 工作方式 → 角色节点 | 能解释一个任务从接收至结果的链路 |
| 角色与世界兴趣访客 | 认识成员人格和工作场景 | 团队 → 世界 | 能从角色进入对应工位，不迷失在设定里 |
| 已关注团队的访客 | 查看最近发生了什么 | 情报 | 能按时间、类型和角色阅读记录 |
| 潜在合作/联系访客 | 判断是否值得继续沟通 | 首页/工作方式 → 下一步 | 看见诚实的联系状态和待确认内容，不被虚假承诺误导 |

### 2.2 不服务的假设任务

当前官网不承担登录、产品试用、下载、充值、客户自助服务、招聘投递或真实运维监控。未来若要承担，必须先有内容、业务和技术确认，标注为“待内容确认/待外部研究”。

## 3. Content Model

### 3.1 内容实体

```ts
type EvidenceKind = 'work' | 'join' | 'complaint';
type AgentStatus = 'available' | 'working' | 'building' | 'unknown';

interface AgentRole {

```

```ts
interface TaskroomHome {
  heroMedia: { videoUrl?: string; posterUrl: string; transcriptUrl?: string };
  thesis: string;
```

### 3.3 内容规则

- “已确认”只写项目事实、已发布情报或内容负责人批准的文案。
- “待内容确认”用于联系方式、业务入口、视频字幕、服务范围、案例和任何未落地的 CTA。
- “待外部研究”用于市场定位、访客数据、竞品比较、行业术语验证；本报告不把这些内容写成已知结论。
- 当前状态没有来源时显示 `状态未知`，不得用绿色点、百分比或“在线”暗示系统事实。
- 首页精选证据最多 3 条，直接复用情报数据，不复制一套新闻实体。
- 未来若加入真实任务记录，应增加时间、角色、动作、工具、结果和权限状态；在数据未确认前不做任务回放。

## 5. Page Specs

## 5.1 首页：任务现场

### 用户任务

在 10 秒内理解 Promise AI 是 Agent 工作室；看见至少一个真实工作证据；选择进入情报、团队、工作方式或世界。

### 页面结构

1. 全局导航
2. `TaskroomHero` 任务现场首屏
3. `EvidenceStrip` 三个事实切片：任务、工具、结果（具体数据/文案待内容确认；没有数据时只展示能力事实）
4. `RoleNetworkPreview` 四个角色及关系
5. `LatestSignals` 最新情报 1–3 条
6. `SystemTeaser` 工作方式流程摘要
7. `WorldPreview` 工作空间与愿景入口
8. `NextStepPreview` 下一步状态
9. 页脚

### 首屏结构

桌面采用左侧信息、右侧现场媒体的 5/7 列结构：

- 顶部小标：`PROMISE AI / TASKROOM`；
- H1：`让任务被接住，继续向前。`；
- 支撑句：`一个由 AI Agent、工具执行、记忆与调度组成的工作室。`；
- 主 CTA：`看它如何工作` → 工作方式；
- 次级链接：`查看最新情报` → 情报；
- 右侧为视频或 poster，配“现场片段 / 可暂停”标记；
- 首屏底部显示 `角色 / 证据 / 系统 / 世界` 四个路线索引。

H1 是观点句，不是夸张的“世界第一”自证；品牌名和“AI 工作室”必须在 DOM 中同屏可见。正式营销口号若必须使用“世界第一”，放在品牌副标题并标记为品牌自称，不把它当业务证明。

### 关键内容模块

- **EvidenceStrip：**三列或三行，分别解释 Agent、工具执行、记忆/调度。不得写不存在的完成量。
- **RoleNetworkPreview：**中枢小夜连接小黑、小优、小美；连接线表达关系，不表达实时通信，除非已有事件数据。
- **LatestSignals：**只显示真实情报字段：类型、标题、日期、作者、摘要（若有）。
- **SystemTeaser：**静态 5 步：接收任务 → 理解上下文 → 选择/调用工具 → 返回结果 → 进入下一步。该流程是产品能力解释，不是假装实时回放。
- **WorldPreview：**三张工位图优先，都市愿景图单独标记“未来/愿景”。
- **NextStepPreview：**当前显示“联系入口待内容确认”；仍提供“继续查看工作方式”和“阅读情报”。

### 导航关系

首屏主入口指向工作方式，证据模块指向情报，角色网络指向团队，工位图指向世界；页面不使用同权重的四个大按钮。

### 桌面/移动布局

- 桌面 ≥1200：12 列；首屏 5/7；证据三列；角色关系图与说明并排。
- 平板 768–1199：8 列；首屏改为上媒体下文案或 4/4；证据两列；关系图缩小。
- 移动 <768：媒体先行但高度固定，文案独立置于其下；主 CTA 满宽，次级链接文本化；全部模块单列；角色关系改为“中枢 → 子代理”的纵向列表。

### 交互和动效

- 视频默认静音、循环、内联播放；提供暂停/播放控制和 poster。
- 角色关系只做 hover/focus 高亮，不做自动轨迹或模拟消息流。
- 证据切片滚动进入时淡入 180ms；`prefers-reduced-motion` 下直接呈现。
- 主 CTA 进入页面并更新 active 导航；浏览器后退可回到来源锚点。

### 空状态、错误状态、视频失败状态

- 情报为空：显示“暂时没有可发布的情报”，提供“查看团队职责”。
- 情报请求失败：显示“情报暂时无法读取”，若使用缓存必须明确写“显示项目缓存内容”。
- 角色/世界资产失败：保留固定比例框，显示姓名/名称和文字描述，不能让布局跳动。
- 视频失败、被浏览器阻止或低带宽：自动落到 poster + 完整文案；不显示技术错误码。
- 内容未确认：显示中性标签“内容待确认”，隐藏不可用的按钮 destination。

### 无障碍要求

- 只有一个 H1；模块使用 H2；证据、情报、角色使用 list/article。
- 连接线不承载唯一语义，DOM 中必须有“谁与谁如何协作”的文字。
- 视频不是唯一信息来源；提供暂停、poster 和文字说明。
- 所有 CTA 可键盘操作，焦点环对比度足够；触控区域 ≥44px。
- 进入情报异步更新使用 `aria-live=polite`，不重复朗读整个首页。

## 5.2 情报 / Signals

### 用户任务

确认团队最近公开记录了什么；按类型、日期、角色读取上下文；区分已确认内容、缓存内容和空状态。

### 页面结构

1. 页面标题与一句解释：`工作室留下的可读记录`。
2. 过滤器：全部 / 工作 / 入职 / 牢骚。
3. 情报时间线/列表。
4. 单条详情展开或详情页。
5. 相关角色入口。
6. 下一步推荐：工作方式、团队。

### 首屏结构

左侧标题、右侧当前筛选和最新记录摘要；第一条情报进入首屏下半部。不要用大图轮播抢走记录阅读任务。

### 关键内容模块

- `SignalFilter`：按钮组，当前项有文字与 `aria-current`。
- `SignalList`：`time`、类型、标题、作者、摘要、详情入口。
- `SignalDetail`：保留来源和日期；不把普通团队动态扩写成商业案例。
- 生活照若要绑定情报，必须先完成内容归属确认；否则仅作为独立视觉素材或不使用。

### 导航关系

从首页精选记录进入对应详情；详情可回到相关角色或工作方式；顶部导航可直接进入团队/系统。

### 桌面/移动布局

桌面为左筛选栏 + 右时间线；移动为顶部横向可滚动筛选、单列记录；每条记录的点击区域不小于 44px。长正文在移动端自然增长，不套固定高度。

### 交互和动效

筛选只更新列表，不自动滚动页面；URL 保留筛选参数。加载 skeleton 仅模拟结构，不模拟真实记录。新增内容若有 API，使用 150ms 列表替换，减少模式不做过渡。

### 空状态、错误状态、视频失败状态

- 无记录：按当前筛选显示“该分类暂时没有情报”；提供清除筛选。
- API 失败：明确“读取失败”，给出重试；若有缓存，标记缓存日期。
- 图片失败：记录仍可读，图片区域替换为类型色条和文字。
- 本页不需要视频；若未来使用视频，按首页 HeroMedia 规则处理。

### 无障碍要求

过滤器使用 `role=tablist` 或明确按钮组，不混用；列表使用 `<ol>`/`<article>`；类型不能只用粉色/紫色区分；详情展开按钮说明“展开/收起标题”。

## 5.4 工作方式 / System

### 用户任务

理解 Agent、工具、记忆、调度、微信通道以及工程/运维/设计子代理之间的真实关系，判断官网展示的是能力模型而非虚构成果。

### 页面结构

1. 任务链总览。
2. Agent Loop：理解上下文 → 决策 → 工具执行 → 结果。
3. 角色路由：小夜中枢 → 小黑/小优/小美。
4. 记忆：上下文如何保留，文案只写已确认能力。
5. 工具和权限：工具执行的事实说明；不展示未确认的工具列表。
6. 微信通道：说明是文字通道；涉及高风险动作需要文字授权，具体权限文案以现有规则为准。
7. 任务证据入口：链接情报，不伪造实时任务。

### 首屏结构

左侧 H1：`工作不是一句回复，而是一条可解释的链。`；右侧为静态流程图：`任务 → Agent → Tool → Result → Memory / Next step`。流程每个节点都有可读文字和展开说明。

### 关键内容模块

- `SystemFlow`：五步流程，静态优先。
- `AgentRouter`：小夜负责理解需求、拆解任务、派单和监督协调；小黑工程、小优运维、小美产品/UI/视觉设计。
- `ToolExecutionNote`：工具执行是系统能力，不展示不存在的成功数字。
- `MemoryPanel`：解释记忆在任务上下文中的作用；具体检索算法、召回率或容量为待外部研究/待产品确认。
- `ChannelNote`：微信为文字审批通道；不暗示语音、电话、SIP 等未纳入当前官网事实的产品。
- `EvidenceLink`：引导查看已有情报。

### 导航关系

系统页是首页主 CTA；从角色页的“工作边界”进入对应系统步骤；从系统说明进入情报记录；系统页不提供虚假的“开始任务”按钮。

### 桌面/移动布局

桌面 12 列：流程图占 8 列，解释占 4 列；角色路由以纵向链路呈现。移动将流程改为纵向步骤，任何横向关系图都必须有 DOM 顺序文本；不强制横向拖拽才能读懂。

### 交互和动效

步骤点击展开说明，默认只展开当前/第一步；无自动播放。连接线可用 CSS/SVG，但不得承载唯一信息。动效只反馈选择，不模拟数据包或实时工作。

### 空状态、错误状态、视频失败状态

- 具体任务记录未接入：显示“公开任务回放待内容确认”，保留静态能力流程。
- 组件加载失败：显示流程的文字版顺序。
- 无权限/受限细节：显示“此信息未公开”，不显示空白。
- 页面不需要视频；若复用首页片段，提供 poster 和同样降级。

### 无障碍要求

流程使用有序列表；每个节点有标题、说明和关系；颜色、动画、连接线都不是唯一语义。展开控件有 `aria-expanded`，键盘可顺序阅读。涉及授权的说明必须以文字明确“需要授权/不需要授权”，不只用锁图标。

## 8. Design Tokens

### 8.1 色彩

现有 `#1d1d1d / #50e5fb` 不作为整套新设计的唯一视觉答案，但不应简单抹掉品牌连续性。新系统让深色只承担“工作现场背景”，让青色只承担“可操作路径/当前状态”，并加入偏暖中性色以区分普通 SaaS 控制台和游戏官网霓虹。

| Token | Value | 用途 |
|---|---|---|
| `--color-ink-950` | `#101112` | 页面底色、深色现场 |
| `--color-ink-900` | `#17191A` | 导航、深色内容带 |
| `--color-ink-800` | `#222628` | 面板/关系图底 |
| `--color-paper-100` | `#F3F1EB` | 证据阅读区的暖白 |
| `--color-paper-200` | `#E5E2D9` | 暖灰背景和分隔 |
| `--color-text-on-dark` | `#F5F5F0` | 深色标题 |
| `--color-text-muted-dark` | `#B7BCBA` | 深色正文，需对比度验证 |
| `--color-text-on-light` | `#17191A` | 浅色正文 |
| `--color-line-dark` | `rgba(245,245,240,.16)` | 深色分隔 |
| `--color-line-light` | `rgba(23,25,26,.16)` | 浅色分隔 |
| `--color-signal` | `#67D9E8` | 当前、路径、主行动 |
| `--color-signal-ink` | `#063B43` | 青色按钮文字 |
| `--color-work` | `#D99B45` | 工作类情报语义 |
| `--color-join` | `#B78BE8` | 入职类情报语义 |
| `--color-complaint` | `#EF7595` | 牢骚类情报语义 |
| `--color-error` | `#E06B62` | 错误 |
| `--color-success` | `#77B889` | 已确认/成功，仅有真实状态时使用 |

**为何放弃单一 `#1d1d1d/#50e5fb`：**单色深底 + 高亮青色容易落入“赛博游戏官网”或“技术 SaaS 仪表盘”的惯性。新系统保留深色和青色的识别关系，但通过暖白阅读区、橙/紫/粉的严格语义色和无光晕边界建立“工程系统 + 角色人格 + 世界叙事”的混合气质。青色面积控制在约 8%–10%，不使用全局发光。

所有颜色实际上线前须用浏览器/axe 或对比度工具验证；视频背景上的文字必须依靠局部遮罩和安全区，而不是文字阴影。

### 8.2 字体

```css
--font-ui: "Inter", "PingFang SC", "Noto Sans SC", system-ui, sans-serif;
--font-display: "Noto Serif SC", "Songti SC", serif;
--font-mono: "IBM Plex Mono", "SFMono-Regular", ui-monospace, monospace;
```

- UI、职责、流程说明使用无衬线，体现清晰和工程可信度。
- `--font-display` 只用于页面标题中的少量观点词，不用于整段角色设定，避免回到 Studio Editorial。
- 等宽字体用于日期、事件编号、状态和流程节点标签。
- 字重只用 400/500/600/700；letter-spacing 默认 `0`，不使用负字距。
- 正文 16px 起；行高 1.6–1.8。

### 8.3 网格与尺寸

- 基准间距 4px。
- 桌面最大内容宽度 1280px；宽屏两侧保留可呼吸区域。
- ≥1200px：12 列，列间距 24px，页面左右 padding 48–64px。
- 768–1199px：8 列，列间距 20px，左右 padding 32px。
- <768px：4 列，列间距 16px，左右 padding 20px，底部加 safe-area inset。
- 页面 section 内间距：紧凑 16/24px，模块 40/48px，页面段落 96/128px。
- 可点击行、按钮、tab 最小高度 44px。
- 图像容器必须设置 `aspect-ratio` 或固定 grid track。

### 8.4 边框、圆角、阴影

- 线宽：1px；结构优先使用边框和留白。
- `--radius-none: 0px`：现场媒体、愿景大图、页面分区。
- `--radius-sm: 4px`：情报条目、按钮、输入框。
- `--radius-md: 8px`：面板和关系图容器。
- 禁止默认大圆角和胶囊化页面。
- 默认阴影 `none`；浮层用 `0 8px 24px rgba(0,0,0,.18)`；不为视频和角色立绘加光晕。
- hover 只改变边线、背景或轻微 translateY(-2px)，不改变布局尺寸。

### 8.5 图像处理

- 人物立绘保留透明背景和完整轮廓，不套头像圆形裁切。
- 工位图按内容安全区裁切，桌面 `object-fit: cover`，移动端根据每张图配置 `object-position`。
- 视频使用明确 poster；都市愿景始终有“未来/愿景”标签。
- 不给所有图片统一深色模糊滤镜；必要时只为文字安全区使用局部遮罩。
- 装饰图 `alt=""`，信息图提供准确 alt，不能把“氛围”写成业务事实。

## 9. Motion

### 原则

动效表达三种关系：进入现场、切换上下文、确认状态。不得用动效制造“系统正在工作”的假象。

| 场景 | 动效 | 时长 | reduced motion |
|---|---|---:|---|
| 页面/模块进入 | opacity + 8px 位移 | 180–240ms | 直接出现 |
| 角色/工位切换 | cross-fade | 200ms | 直接替换 |
| tab/筛选 | 背景或边线变化 | 150ms | 直接变化 |
| CTA hover | 颜色/边线 | 150ms | 直接状态 |
| 视频 | 用户可控循环 | 原视频 | poster |
| 加载 | 轻量 skeleton | 不超过必要时间 | 静态占位 |

- 不使用持续闪烁、呼吸光、粒子、鼠标跟随、重视差和自动滚动。
- 不用 scroll-snap 强制移动端阅读节奏；桌面可对首屏舞台做轻量吸附，但必须支持键盘和自然滚动。
- 所有动效遵守 `prefers-reduced-motion`。

## 10. Responsive

### 桌面 ≥1200px

- 全局导航固定但不遮挡内容；当前页用文字和线条指示。
- 首页首屏媒体/文案 7/5；系统流程图可横向呈现，旁边有文字版。
- 角色关系图和证据列表并排，使用 12 列。
- 情报列表密度提高但保留每条至少 56px 行高。

### 平板 768–1199px

- 导航可折叠或横向滚动，当前页始终可见。
- 首页媒体在上、文案在下或 4/4 并排，取决于实际视频安全区。
- 关系图转为顶部选择 + 纵向关系列表。
- 情报过滤器保持单行可滚动，不缩到难以点击。

### 移动 <768px

- 站点结构自然流式，不强制每页一屏。
- 首屏媒体固定比例，品牌文案独立在深色内容带；H1 允许两行。
- 移动菜单带明确打开/关闭状态，Esc 返回焦点。
- 角色立绘与职责分离排版，避免文字覆盖人物脸部/关键资产。
- 工作方式流程纵向编号；每一步文本必须可直接阅读。
- 表格改为条目；横向滚动仅用于明确的 tab，不把主要信息藏在横滑画布中。
- 图片 lazy-load，视频可在低带宽直接使用 poster。

### 短视口和横屏

顶部导航、品牌名和当前页面标题必须保持可见；首屏 CTA 不放在可能被浏览器地址栏/安全区遮挡的位置；任何绝对定位内容都必须有自然流布局备份。

## 11. Accessibility

- 页面语言 `lang="zh-CN"`；所有英文标签都有中文语义陪同。
- 每页一个 H1；H2/H3 按信息层级使用，不按视觉字号跳级。
- 键盘 Tab 顺序与视觉阅读顺序一致；无键盘陷阱。
- `:focus-visible` 使用至少 2px 轮廓 + 2px offset，颜色在深浅背景均可见。
- 正文对比度 ≥4.5:1，大文本 ≥3:1；弱化色不用于正文。
- 触控目标 ≥44×44px；相邻操作至少 8px 间距。
- 图片使用功能性 alt；人物、工位、愿景的描述不重复周围标题。
- SVG/连接线提供文本替代；颜色、位置、动画不作为唯一状态。
- 视频提供暂停，自动播放静音；视频失败不影响文本任务。
- 异步状态使用 `aria-live="polite"`，加载/失败/缓存/空状态有明确文本。
- 角色/场景切换维护焦点，不把焦点丢到页面顶部。
- 未来表单必须有 label、错误关联、提交成功/失败反馈、隐私说明；当前未确认前不显示假表单。
- 文字不使用 viewport 字体缩放；长中文和英文单词允许换行，不溢出父容器。
- 视觉 QA 必须覆盖 390×844、1440×900、键盘操作、reduced motion、视频失败和图片失败。

## 13. Implementation Plan

本节是实现顺序和验收契约，不代表本轮改动生产代码。

### Phase 0：内容与路由确认

1. 内容负责人确认品牌称谓、首页支撑句和四位成员公开资料。
2. 确认小美是否作为现有官网成员公开展示；若当前 API 只有三人，补充内容字段后再渲染，不在前端硬编码伪造。
3. 确认真实情报字段、日期格式、缓存语义和详情策略。
4. 确认新 URL 与旧 hash 深链映射。
5. 确认联系入口；未确认前实现 Pending Contact 状态。

### Phase 1：内容模型和页面壳

1. 保留现有数据实体，补充最小聚合配置，不复制 Role/News/World/City 数据结构。
2. 建立 GlobalNav、PageIntro、StatusLabel、ContentState、MediaStage。
3. 实现 `/`, `/signals`, `/team`, `/system`, `/world`, `/contact` 页面骨架。
4. 确保无 JS、API 失败和视频失败时仍有核心文本和导航。

### Phase 2：首页与系统页

1. 先实现 TaskroomHero：文本优先，视频可插拔。
2. 实现 EvidenceStrip、AgentRouter 和 SystemFlow。
3. 将情报精选作为真实数据引用，不创建模拟任务回放。
4. 实现“中枢 → 工程/运维/设计”的关系文本和可选图形化表达。

### Phase 3：团队、情报、世界

1. 团队页以小夜为默认入口，角色切换可深链。
2. 情报页完成分类、时间、作者、缓存/失败/空状态。
3. 世界页完成工位图和愿景分层。
4. 生活照只有完成内容归属确认后才进入情报。

### Phase 4：视觉实现和资产 QA

1. 应用新 tokens，删除 Studio Editorial 的个人主页样式。
2. 检查视频安全区、立绘裁切、工位图 object-position、愿景标签。
3. 检查没有卡片套卡片、没有无语义装饰节点、没有大面积渐变/光晕。
4. 用浏览器截图检查桌面、移动、短视口和横屏。

### Phase 5：无障碍和回归

1. 键盘完成全站导航、角色切换、筛选、展开和返回。
2. 使用 axe/对比度工具验证文本、按钮、焦点和媒体替代。
3. 测试 `prefers-reduced-motion`、视频阻止、图片失败、API 超时、空数据。
4. 验证旧 hash 深链和浏览器后退行为。
5. Visual QA 由小美执行，问题以 PASS/FAIL + 截图/路径证据记录；小黑按 DESIGN_SPEC 修复，小优验证部署和失败回退。

### 工程禁区

- 本轮不做登录、下载、充值、电话、SIP、车机、复杂工作流、真实监控控制台。
- 不添加未经确认的客户、营收、SLA、案例、服务报价、招聘或成功率。
- 不用前端定时器伪造实时状态。

## 结论

**推荐方向：任务现场 / Taskroom。**

它把 Promise AI 官网从“AI 角色展示页”改成“Agent 如何接住并推进任务的公开解释层”：首页负责建立认知，情报负责提供时间证据，团队负责说明角色关系，工作方式负责解释系统，世界负责承载上下文与愿景，下一步负责诚实地处理联系缺口。现有资产全部有位置，但没有任何一项资产再被允许单独冒充事实。
