# 组件规则（Component Rules）

> 维护者：小美；依据：CEO 规格「Design System 优先：检查页面是否违反」。

## 核心立场

**组件必须来自 Design System，页面内不允许自造。** 组件是设计语言的"单词"，
自造组件 = 造新词，用户和开发都要重新学。

## 通用规则（所有组件）

- 每个组件只有一种正确形态；形态差异必须绑定语义差异（主/次、状态）。
- 状态完整：default / hover / active / focus / disabled / loading / error 都要定义，
  缺状态说明设计没做完。
- 焦点态（focus-visible）必须可见：键盘用户与无障碍用户依赖它。
- 文字不做纯装饰：按钮上的文字必须是动作（"保存"不是"我们正在保存"）。

## 按钮层级（Primary / Secondary / Ghost）

| 层级 | 形态 | 用途 |
|---|---|---|
| Primary（主） | 实心 accent 或深底 + 白字 | 每屏只有一个，页面唯一的下一步 |
| Secondary（次） | 1px 描边 + 透明底 | 与主行动并列的次级行动 |
| Ghost（幽灵） | 无边框，hover 才显底 | 低干扰行动 / 工具栏 |
| Danger | 错误色实心或描边 | 删除/不可逆操作（配确认弹窗） |

- 主按钮每屏至多一个；两个主按钮 = 没有主按钮。
- 危险操作按钮颜色 ≠ 品牌色：用户必须一眼认出"这步有风险"。

## 表单

- 标签永远可见（占位符不是标签——输入后占位符消失，用户就忘了这格填什么）。
- 必填标注：默认全部必填，只标"选填"（比星号风暴更少噪音）。
- 校验错误：字段级报错（靠近字段）+ 可读文案（"邮箱格式不对"而非"输入无效"）。
- 输入框高度 ≥ 40px、点击区域 ≥ 44px。

## 卡片

- 结构固定：内容区 + 统一内边距（16/24px 二选一）+ 可选页脚区。
- 卡片不嵌套卡片（嵌套两层以上说明信息架构有问题）。
- 卡片 hover 态：轻量（描边转 accent 或 2px 上浮），不加夸张阴影。

## 列表与表格

- 行高统一（≥ 44px 触控行）；行 hover 有轻反馈。
- 表格：对齐规则（文本左、数字右/等宽）、列宽稳定、表头不滚动消失（必要时 sticky）。
- 空状态必须设计（"没有数据"≠ 空白页）：给用户下一步指引。

## 导航与标签

- 全局导航与页面内导航形态分离，但都来自 Design System。
- Tab 激活态对比明显（accent 高亮），用户永远知道"我在哪"。
- 面包屑/步骤条：只在流程 > 2 步且用户会迷路时使用。

## 弹窗与抽屉

- 弹窗必须：有标题、有明确关闭路径（× + 取消）、遮罩点击行为明确（关/不关二选一并全项目一致）。
- 确认破坏性操作：弹窗内用 Danger 按钮 + 明确后果文案（"永久/不可恢复"）。
- 弹窗不套弹窗。

## 图标与动效

- 图标来自同一套图标库（线性/填充全项目一致），同义图标全站唯一。
- 动效：150–300ms 过渡；动效必须服务于状态反馈或空间关系，不服务炫技。
- 尊重 `prefers-reduced-motion`：用户要求减动效就减。

## 何时用何时不用

- 用：新页面时先查组件库，能拼则不画。
- 不用：现有组件差一点就"临时改一版"——先确认改的是组件还是用例；
  组件缺陷回组件库修，用例差异在页面层组合，两层都别污染。
