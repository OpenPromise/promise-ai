# 间距原则（Spacing）

> 维护者：小美；依据：CEO 规格「视觉方向：间距取舍理由」+ 官网 style-guide（4px 基准）。

## 核心立场

**留白是设计的一部分，不是"没填满"。** 间距承担分组与层级的功能——间距大的区块
暗示"内容上的分离"，间距小暗示"内容上的关联"。好的间距让用户不用读文字就能感知
结构。

## 基准网格

- 以 **4px 为最小单位**，间距一律取 4 的倍数：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64。
- 不建议引入 6px 系或 5px 系（两套网格并存会制造无数"差 1px"的纠结）。
- 语义化 token：`--space-1:4px` … `--space-8:64px`，页面内不写裸数字。

## 节奏规则

| 场景 | 建议 |
|---|---|
| 元素内部（图标与文字、标签内边距） | 4–8px |
| 同组元素之间（表单字段、列表项内部） | 8–16px |
| 相邻组件之间（卡片与卡片） | 16–24px |
| 区块之间（板块与板块） | ≥ 48px |
| 全屏页内容区 padding | 6vw–7.5vh 档（大屏宽松，小屏收窄） |

- **间距层级必须和内容层级同步**：越重要的分组之间留白越大。
- 垂直节奏比水平节奏更重要（滚动阅读场景）；垂直间距优先于水平间距被遵守。

## 密度（信息密度控制）

- 信息密度 = 单位面积信息量。工具类界面（看板/表格/IDE）允许高密度，
  消费类界面（落地页/设置引导）用低密度。
- 密度决策写进 DESIGN_SPEC 的 Page 段，别让开发猜。
- 高密度≠挤：即使信息多，也要用间距保住分组与扫读路径。

## 组件内间距（一致性来源）

- 同类组件的内边距全局一致（按钮、输入框、卡片同一 token）。
- 卡片内容区边距：`16px（紧凑）/ 24px（标准）`二选一，全项目统一。
- 列表项行高统一（如 44px 触控行高），不做"每行随心情"。

## 何时用何时不用

- 用：分组、层级、呼吸感、聚焦。
- 不用：用间距硬凑排版问题（该合并的信息拆散了、该分离的贴一起），
  先检查信息架构对不对，再谈间距。
- 响应式：小屏按比例收窄间距（clamp 或断点切换），不做像素级等比缩放强迫症。
