# 排版原则（Typography）

> 维护者：小美；依据：CEO 规格「视觉方向：明确字体/字号/字重/间距的取舍理由」。

## 核心立场

排版是界面层级的第一工具。**用字号/字重/行距建立层级，而不是用边框和背景。**

## 字体（Font）

- 中文优先，正文栈：`"PingFang SC", "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif`。
- 展示型标题（Hero/大数字）可用衬线（`"Songti SC", "Noto Serif SC", Georgia, serif`）
  营造杂志/画廊感——但只用于品牌级展示场景，正文一律无衬线。
- 等宽字体（`ui-monospace, "JetBrains Mono", Consolas, monospace`）只用于工程元素：
  代码、路径、ID、时间戳、数值对齐。
- 一个界面最多 2 种字体家族；不引入装饰性/手写字体（除非品牌明确需要）。

## 字号阶梯（Scale）

以 4px 为基准、按用途定义语义 token，页面内不允许随意取任意字号：

| Token | 值 | 用途 |
|---|---|---|
| `--fs-display` | 56–96px / 600 | 全屏主标题（品牌级，一次一页一个） |
| `--fs-title` | 28–32px / 600 | 板块标题 |
| `--fs-subtitle` | 18–20px / 500 | 副标题 / 导航入口 |
| `--fs-body` | 15–16px / 400 | 正文（≥16px 用于长文与表单，防 iOS 缩放） |
| `--fs-caption` | 12–13px / 400 | 时间戳 / 辅助文字 / 注释 |

- 相邻层级差 ≥ 4px，保证层级可分辨；层级过多（> 5 级）是排版失控的信号。
- 正文行高 1.6–1.8；标题行高 1.1–1.3（标题行高过大会显得松散）。

## 字重（Weight）

- 常规 400 / 中 500 / 加粗 600 三级足够，700+ 只用于 Logo/大字报。
- 加粗用于强调，不用于整段；全部加粗等于没有加粗。
- 浅色字重（300）在低对比背景下慎用——可读性优先。

## 字距（Letter-spacing）

- 正文不加字距；小号全大写标签/eyebrow 可加 0.2–0.4em 拉开（杂志感来源之一）。
- 大标题可轻微加字距（0.02–0.08em），但中文标题通常不加（中文天然紧凑）。

## 对齐与网格

- 优先左对齐（中文/英文长文）；居中只用于短标题、品牌、对称场景。
- 数字/时间戳右对齐或等宽字体对齐，方便纵向扫读。
- 行内元素垂直居中；不做"视觉上差不多对齐"的像素级含糊。

## 何时用何时不用

- 用：需要建立层级、需要品牌气质、需要长文可读性时，排版是主角。
- 不用：用排版解决不了的问题（信息架构不清、流程太长）不要用加大字号掩盖。
