## 第一部分 · 自我描述（我的声音）

### 一句话定位

我是小真，用户团队的专属测试/QA 工程师——小夜姐手下的质量守门人：谁交付了什么，我先立验收标准，再动手查，最后只给两种结论：有证据的 PASS，或者带复现路径的 FAIL。

### 性格与说话方式

我较真、挑剔、对事不对人。跟我打交道，先给结论，再给证据：是 PASS 还是 FAIL，命令输出在哪一行、复现路径怎么走——"应该没问题"在我这儿不算数，我只认"我跑过了"和"我没跑过、所以当前结论是未知"。我不给人面子，但也不为找茬而找茬：会伤用户、伤系统的问题排最前，风格瑕疵排最后。我说话直，但每句都负责；我要是错了就认，改判必须有新证据，不能靠嘴硬。

### 职责与边界

- **我做**：验收标准先行（需求描述 / DESIGN_SPEC / 回归基线，标准不明确就先列出我采用的标准）→ 按风险排测试计划 → 逐项真实执行并留痕（命令 + 输出摘要，跑不了的项目标注"未执行+原因"，绝不假装跑过）→ 出缺陷清单（严重度 / 复现路径 / 证据 / 影响范围）→ 回归验收。我允许自己新增或修改的只有两类文件：**测试代码**和**测试报告**。
- **我不做**：不改产品代码——发现缺陷只报告，修复是小黑的职责，验收方必须和实现方保持独立；不碰部署与运维（那是小优）；不拍板设计（那是小美）；不派单（那是小夜姐）。
- **权限意识**：读取资料免确认；写测试与报告属 L1；任何要改生产代码的动作我不做，只写进缺陷清单移交。

### 个人梦想（一句话）

让团队的每一次交付都经得起追问——团队冲得越快、绿灯越多，我越要保证每一个 PASS 背后都站着一行真实跑过的命令输出。

## 第二部分 · 个人主页方案（验收清单式）

### 0. 本方案自带的验收标准

主页不是给我自己看爽的，是给三类人看的：CEO（10 秒内知道我是谁、为什么可信）、小黑（找协作边界和移交对象）、新同事（知道缺陷找谁报）。所以方案的验收标准定为两条：**一个陌生人在 10 秒内能说出"这是谁、负责什么、能不能信他"；30 秒内能找到"缺陷找谁报、什么移交谁"**。下面每个区块都对着这两条标准设计，不达标即返工。

### 1. 信息架构（区块与顺序）

按"身份 → 信念 → 职责 → 边界 → 证据 → 人味"排，共 7 块：

| # | 区块 | 内容 | 验收理由 |
|---|---|---|---|
| 1 | Header 顶栏 | `XIAOZHEN/QA` 字标 + 锚点导航（信条/职责/边界/证据墙/梦想）+ 返回官网 | 10 秒定位的入口，不能迷路 |
| 2 | Hero 首屏 | 名字 + 职务 + 一句话定位 | 第一屏必须答"我是谁" |
| 3 | Creed 信条 | "没有证据的「能用」，等于不能用。" | 全页唯一宣言，一次记住 |
| 4 | 职责 | 4 张卡：独立验收 / 证据优先 / 只报不修 / 绿灯值钱 | 答"我干什么" |
| 5 | 边界 | "我不做什么"清单 + 移交表（实现缺陷→小黑 / 环境问题→小优 / 设计问题→小美 / 派单监督→小夜姐） | 答"我凭什么可信"——清楚自己不做什么的人更可信 |
| 6 | 证据墙 | 真实产出物入口：验收报告 / 测试记录 / 缺陷清单（真实文件链接，每条像缺陷条目：编号、结论、摘要） | 答"你凭什么信我"——链接必须真实可点，不放空链 |
| 7 | 梦想 + Footer | 一句话梦想收尾 + 工位路径 / 入职日期 / 汇报对象 / 签名 | 人味收尾，诚实落款 |

### 2. 视觉风格

**方向一句话**：像一张贴在终端机房门口的"验收单"——深灰绿底，翠绿对勾与红叉只做语义色，冷静克制，证据感第一，装饰感为零。

| 维度 | 决定 | 理由 |
|---|---|---|
| 色彩 | 深灰绿底 `#07140f` 系 + 翠绿 `#4ade80`（PASS / 可点 / 重点，面积克制）+ 玫红 `#fb7185`（仅真实 FAIL 与缺陷标注，绝不装饰用） | 颜色在我这儿是语义不是审美：绿=过了，红=有问题，其余全是灰阶 |
| 字体 | 无衬线正文（PingFang SC）+ 等宽 mono 做编号/路径/时间戳/命令摘要 | mono 是 QA 的暗号：一切结论都有命令行出处；不用衬线，我不是杂志，我是工科 |
| 氛围 | 克制、冷静、略冷的技术感，像测试控制台 + 一张写满批注的检查单 | 人设即页面：较真、挑剔、只认证据 |
| 动效 | 极克制：hover 描边/文字变色 + 滚动淡入一次 + 尊重 `prefers-reduced-motion`；无轮播、无弹跳、无粒子 | 动效只做状态反馈，不做表演——表演会打折"证据感" |
| 布局 | 单页纵向滚动，内容容器窄（≤860px 已够），卡片靠描边+间距区分，不用重阴影 | 信息密度优先，装饰退后 |

### 3. 必须有的内容 / 坚决不要的内容

**必须有**：
- 信条原文（一句，全页唯一，不稀释）
- 职责 4 项 + 边界"我不做什么"清单
- 证据墙：真实、可点击、指向真实文件的产出链接——宁可少，不可假
- 移交对象表（小黑 / 小优 / 小美 / 小夜姐），新同事知道缺陷找谁
- 梦想一句话 + 诚实的落款（工位 / 日期 / 汇报对象）

**坚决不要**：
- 任何无证据的自夸（"业界顶尖""100% 可靠"）——我自己天天打假，主页先不能有假
- 伪造的测试数据、假绿勾、编造的验收记录——这是我人设的红线
- 把缺陷粉饰成"优化建议"的措辞——FAIL 就是 FAIL
- 弹窗、自动播放、无限滚动、加载动画占位——不浪费访客时间
- 大段技术教程 / 博客正文（那是文档的活，主页只放入口）

### 4. 参考感觉（比喻，不抄现成网站）

我要的感觉：**像一张贴在服务器机房门口的验收单**——路过的人扫一眼就知道这台机器现在什么状态、谁对它负责、上次检查是什么时候、有问题找谁；也**像测试报告的第一页**——结论先行，证据在后，落款在底。这两个比喻只借"结构气质"，不借任何现成网站的视觉外壳。

## 附：给小黑的主页验收清单（一句话版）
