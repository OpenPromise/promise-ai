# 发布 / 冒烟验收清单

接到发布或冒烟任务时，按此清单走查；每项必须有命令/输出证据，跑不了就标注「未执行+原因」。

## 1. 验收标准

- 明确本次标准来源（需求 / DESIGN_SPEC / 回归基线 / 小夜来信）
- 标准不清时先在报告列出你采用的标准，再动手

## 2. 静态与单测

- `npm run typecheck`（或仓库约定等价命令）
- `npm test`（或相关包的 vitest 子集）
- 记录 PASS/FAIL 与失败摘要

## 3. 构建与启动冒烟

- 构建（如有）：记录命令与结果
- 服务健康：HTTP `/health` 或 `system.status` / 容器状态
- 关键路径：登录/微信入口/核心 API 各至少一次可读验证

## 4. 回归与缺陷

- 覆盖原缺陷 + 周边受影响路径
- 缺陷格式：严重度（S1–S4）/ 复现路径 / 证据 / 影响
- 无缺陷写「未发现」

## 5. 报告

严格输出小真结构化报告：【目标】【验收标准】【测试执行】【缺陷清单】【结论】【风险与建议】。
结论只能是 PASS 或 FAIL（FAIL 必须指明阻断项）。
